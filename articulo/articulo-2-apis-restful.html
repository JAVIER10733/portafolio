Diseñando APIs RESTful que los desarrolladores amen usar

Principios de diseño de endpoints, versionado, autenticación JWT, documentación con Swagger y errores consistentes.

YJ
Ythan Javier Mora Gamarra Desarrollador Full Stack · 10 min de lectura
10 min 💬 0 comentarios

Crear una API es fácil. Crear una que otros desarrolladores disfruten usar es un arte. Después de construir decenas de APIs en Node.js y PHP, he aprendido que la diferencia entre una API buena y una excelente está en los detalles.

🎯 Para quién es este artículo

Si ya sabes hacer un GET /users pero quieres llevar tus APIs al nivel profesional, este artículo es para ti.

1️⃣ Nombres claros y recursos

Usa sustantivos en plural y evita verbos en las URLs. La URL debe describir el recurso, no la acción:

❌ Mal vs ✅ Bien 
❌ GET /api/getUsers
❌ POST /api/createUser
❌ GET /api/deleteUser?id=5

✅ GET    /api/v1/users
✅ POST   /api/v1/users
✅ DELETE /api/v1/users/5

2️⃣ Códigos HTTP correctos

No devuelvas siempre 200 OK. Los códigos HTTP son parte del contrato de tu API:

  • 200 OK — Petición exitosa (GET, PUT, PATCH)
  • 201 Created — Recurso creado (POST)
  • 204 No Content — Éxito sin cuerpo (DELETE)
  • 400 Bad Request — Error del cliente (validación)
  • 401 Unauthorized — No autenticado
  • 403 Forbidden — Autenticado pero sin permisos
  • 404 Not Found — Recurso no existe
  • 500 Internal Server Error — Error del servidor
Ejemplo en Express.js 
app.post('/api/v1/users', async (req, res) => {
  try {
    const user = await User.create(req.body);
    res.status(201).json({
      success: true,
      data: user
    });
  } catch (error) {
    if (error.name === 'ValidationError') {
      return res.status(400).json({
        success: false,
        error: error.message
      });
    }
    res.status(500).json({
      success: false,
      error: 'Error interno del servidor'
    });
  }
});

3️⃣ Paginación y filtros

Nunca devuelvas 10,000 registros de golpe. Usa paginación consistente:

Ejemplo de respuesta paginada 
GET /api/v1/users?page=2&limit=20&sort=-createdAt

{
  "success": true,
  "data": [...],
  "pagination": {
    "page": 2,
    "limit": 20,
    "total": 150,
    "pages": 8
  }
}

4️⃣ Errores consistentes

Todos los errores deben seguir el mismo formato. Crea un middleware de errores global:

middleware/errorHandler.js 
const errorHandler = (err, req, res, next) => {
  const statusCode = err.statusCode || 500;
  
  res.status(statusCode).json({
    success: false,
    error: {
      message: err.message,
      code: err.code || 'INTERNAL_ERROR',
      ...(process.env.NODE_ENV === 'development' && {
        stack: err.stack
      })
    }
  });
};

module.exports = errorHandler;

5️⃣ Autenticación con JWT

Usa JWT para autenticación stateless. Nunca guardes sesiones en memoria del servidor:

middleware/auth.js 
const jwt = require('jsonwebtoken');
const User = require('../models/User');

const protect = async (req, res, next) => {
  let token;
  
  if (req.headers.authorization?.startsWith('Bearer')) {
    token = req.headers.authorization.split(' ')[1];
  }
  
  if (!token) {
    return res.status(401).json({
      success: false,
      error: 'No autorizado, token requerido'
    });
  }
  
  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.user = await User.findById(decoded.id).select('-password');
    next();
  } catch (error) {
    res.status(401).json({
      success: false,
      error: 'Token inválido o expirado'
    });
  }
};

module.exports = { protect };
⚠️ Seguridad

Nunca hardcodees el JWT_SECRET. Usa variables de entorno y rota las claves cada 90 días en producción.

6️⃣ Documentación con Swagger

Si no está documentado, no existe. Usa Swagger/OpenAPI:

swagger.yaml (ejemplo) 
/api/v1/users:
  get:
    summary: Lista todos los usuarios
    tags: [Users]
    parameters:
      - name: page
        in: query
        schema: { type: integer, default: 1 }
      - name: limit
        in: query
        schema: { type: integer, default: 20 }
    responses:
      200:
        description: Lista exitosa
      401:
        description: No autorizado

7️ Versionado de API

Usa versionado en la URL para no romper clientes existentes:

Estrategias de versionado 
✅ URL:        /api/v1/users      (más común)
✅ Header:     Accept: application/vnd.api.v1+json
❌ Query:      /api/users?version=1  (evitar)

✅ Checklist de API profesional

  • URLs con sustantivos en plural
  • Códigos HTTP correctos
  • Paginación en endpoints de lista
  • Formato de error consistente
  • Autenticación JWT
  • Rate limiting
  • Documentación Swagger/OpenAPI
  • Versionado de API
  • Logs de peticiones
  • Tests automatizados
🎓 Conclusión

Una buena API es como un buen UI: intuitiva, predecible y bien documentada. Invierte tiempo en el diseño antes de escribir código. Tus compañeros (y tu yo del futuro) te lo agradecerán.
