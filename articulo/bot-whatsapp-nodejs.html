Cómo construir un bot de WhatsApp escalable con Node.js

Guía práctica sobre arquitectura, manejo de sesiones Multi-Device, rate limiting y buenas prácticas para evitar bloqueos en la API de WhatsApp.

YJ
Ythan Javier Mora Gamarra Desarrollador Full Stack · 12 min de lectura
📖 12 min 0 comentarios

Los bots de WhatsApp son una herramienta poderosa para automatizar atención al cliente, ventas y gestión de grupos. Pero muchos desarrolladores cometen el error de crear bots básicos que se bloquean con 50 usuarios. En este artículo te mostraré cómo construir un bot escalable desde el día uno.

⚠️ Nota importante

El uso de bots no oficiales de WhatsApp puede violar los Términos de Servicio. Este artículo es con fines educativos. Para uso comercial en producción, considera la WhatsApp Business API oficial.

🏗️ Arquitectura del sistema

Un bot escalable necesita separar responsabilidades. No puedes tener todo en un solo archivo index.js. Esta es la estructura que recomiendo para proyectos serios:

⚙️ Configuración inicial con Baileys

Usaremos Baileys, la librería más estable para WhatsApp Web API. Instala las dependencias:

Terminal 
npm install @whiskeysockets/baileys
npm install qrcode-terminal
npm install mongoose
npm install ioredis
npm install winston

Conexión Multi-Device

La clave de la escalabilidad es usar Multi-Device, que permite que el bot funcione sin el teléfono conectado:

src/services/whatsapp.js 
const { default: makeWASocket, DisconnectReason } = require('@whiskeysockets/baileys');
const { loadSession, saveSession } = require('./sessionManager');

async function connectToWhatsApp() {
  const session = await loadSession();
  
  const sock = makeWASocket({
    printQRInTerminal: true,
    auth: session,
    browser: ['Bot Pro', 'Chrome', '10.0'],
    syncFullHistory: false,
    markOnlineOnConnect: false
  });

  sock.ev.on('connection.update', async (update) => {
    const { connection, lastDisconnect } = update;
    
    if (connection === 'close') {
      const shouldReconnect = 
        lastDisconnect?.error?.output?.statusCode !== DisconnectReason.loggedOut;
      
      if (shouldReconnect) {
        setTimeout(connectToWhatsApp, 5000);
      }
    }
  });

  sock.ev.on('creds.update', async () => {
    await saveSession(sock.authState.creds);
  });

  return sock;}

🛡️ Rate Limiting (Evitar bloqueos)

WhatsApp bloquea números que envían muchos mensajes rápido. Implementa rate limiting con Redis:

src/middleware/rateLimiter.js 
const Redis = require('ioredis');
const redis = new Redis(process.env.REDIS_URL);

const RATE_LIMITS = {
  PRIVATE:   { window: 60,   max: 20  }, // 20 msg/min
  GROUP:     { window: 60,   max: 10  }, // 10 msg/min
  BROADCAST: { window: 3600, max: 100 }  // 100 msg/hora
};

async function checkRateLimit(userId, type = 'PRIVATE') {
  const key = `rate:${type}:${userId}`;
  const limit = RATE_LIMITS[type];
  
  const current = await redis.incr(key);
  
  if (current === 1) {
    await redis.expire(key, limit.window);
  }
  
  return current <= limit.max;
}
💡 Tip profesional

Usa diferentes límites según el tipo de chat. Los grupos son más sensibles que los mensajes privados. Empieza conservador y ajusta según la respuesta de WhatsApp.

Gestión de sesiones

Las sesiones deben guardarse en base de datos, no en archivos locales. Así puedes escalar a múltiples instancias:

src/services/sessionManager.js 
const mongoose = require('mongoose');

const SessionSchema = new mongoose.Schema({
  phoneNumber: { type: String, required: true, unique: true },
  creds: { type: Object, required: true },
  lastActive: { type: Date, default: Date.now },
  isActive: { type: Boolean, default: true }
});

const Session = mongoose.model('Session', SessionSchema);

async function loadSession(phoneNumber) {
  const session = await Session.findOne({ phoneNumber, isActive: true });
  return session ? { creds: session.creds } : null;
}

async function saveSession(phoneNumber, creds) {
  await Session.findOneAndUpdate(
    { phoneNumber },
    { creds, lastActive: new Date(), isActive: true },
    { upsert: true, new: true }
  );
}

🎯 Comandos modulares

Separa la lógica de negocio del código de WhatsApp. Ejemplo de comando de administración:

src/commands/admin.js 
const commands = {};

commands['!kick'] = {
  description: 'Expulsar miembro del grupo',
  adminOnly: true,
  execute: async (sock, jid, msg, senderId) => {
    if (!jid.endsWith('@g.us')) {
      return sock.sendMessage(jid, { 
        text: 'Este comando solo funciona en grupos' 
      });
    }

    const mentionedJid = msg.message
      .extendedTextMessage?.contextInfo?.mentionedJid;
    
    if (!mentionedJid || mentionedJid.length === 0) {
      return sock.sendMessage(jid, { 
        text: 'Menciona a alguien para expulsar' 
      });
    }

    await sock.groupParticipantsUpdate(jid, mentionedJid, 'remove');
    await sock.sendMessage(jid, { text: '✅ Miembro expulsado' });
  }
};

module.exports = { commands };

Deploy en producción

Para producción, usa PM2 o Docker. Aquí un ejemplo con PM2:

ecosystem.config.js 
module.exports = {
  apps: [{
    name: 'whatsapp-bot',
    script: 'src/index.js',
    instances: 1,
    autorestart: true,
    watch: false,
    max_memory_restart: '500M',
    env: {
      NODE_ENV: 'production'
    }
  }]
};

✅ Checklist de producción

  • Rate limiting activado con Redis
  • Sesiones en base de datos (no archivos locales)
  • Logs centralizados con Winston
  • Reconexión automática ante fallos
  • Manejo de errores global
  • Variables de entorno (.env)
  • Monitoreo de salud del bot
  • Backups automáticos de la base de datos
Conclusión

Un bot escalable no es solo código que funciona, es código que resiste. Invierte tiempo en arquitectura desde el inicio: separa responsabilidades, usa rate limiting, guarda sesiones en BD y monitorea todo. Tu yo del futuro te lo agradecerá.
